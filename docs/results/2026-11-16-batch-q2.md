## Promotion drops the artifact's imports

`FoundationFile.add_artifact` removes every `import` line from an artifact before merging its body
into `LMS/Foundation.lean`, on the assumption that "Foundation has common imports". The header
imports `Mathlib.Tactic.Common`, `Logic.Basic`, `Logic.Function.Basic`, `Data.Nat.Basic` and
`Algebra.Ring.Basic`. An artifact is verified standalone, with its own imports. The merged file
is then rebuilt without them. Every verified artifact in the batch fits this:

| Imports beyond the header | Verified | Kept in the foundation | Rolled back after the build failed |
|---|--:|--:|--:|
| `Mathlib.CategoryTheory.Category.Basic`, `Functor.Basic` (track B, C9, R9) | 12 | 0 | 12 |
| `Mathlib.Algebra.Group.Subgroup.Basic` (track A, 0130) | 1 | 0 | 1 |
| `Mathlib.Algebra.Group.Defs` only, already reached by the header (track A, 012U, 011N) | 2 | 2 | 0 |

The run log records only `Lake build warning: error: build failed`, not Lean's message, so this
was established by the pattern above rather than by an error line. The pattern has no exception.

Before #97, the kernel goals carried a from-scratch `Category` inside the foundation itself, so
category artifacts needed no Mathlib import and this defect stayed hidden. With Mathlib's
`Category` as the only one, every category artifact needs an import the foundation discards.

Two consequences follow:

- **The work never accumulates.** A rollback reopens the tag, and the chair assigns it again. On
  track B, statement 02XK (*strongly cartesian morphism*) was verified **8 times**, in generations
  4, 5, 8, 13, 17, 19, 23 and 24, and the foundation ended the run empty.
- **R9 is C9 in this batch.** R9 resets the foundation each generation; C9 keeps it. Both kept
  nothing, so the comparison between them measures nothing yet. R9's log shows the reset running
  every generation (`reset to seed for generation N: dropped 0 entries`); the collect's "0 resets,
  DISAGREE" line was a pattern in the read script that did not match it.

## Thinking and request timeouts

**Thinking is on.** The model thinks by default, and nothing in the harness or the serve flags
turns it off or caps it. `split_thinking` (#95) keeps it out of the next prompt, but it is still
generated and still counted in every budget, and the trace does not save it.

| | Output tokens (ledger) | Answer text kept | Thinking, estimated |
|--|--:|--:|--:|
| Track B | 5,021,128 | 3,036,348 characters | about 80% of output tokens |
| Track A | 2,309,868 | 1,495,790 characters | about 80% of output tokens |

The estimate takes 3–4 characters per answer token (80–85% on track B, 78–84% on track A). Output
is about 60% of all tokens, so roughly half of every budget goes to thinking that is discarded.

**Three runs ended on `Request timed out.`**: I9 run 5, S1 and R9. Each job spent 900–1,200 s more
than its generations account for. The OpenAI client times a request out at 300 s and retries it
twice, which accounts for 900 s, before the run ends on the exception. One stream generates about
100 tokens/s here, so a reply needs only about 30,000 tokens to time out. `max_tokens` is 64,000,
and an unbounded thinking pass is the likely cause. Because thinking is not saved, this is not
confirmed. The job still exits 0, so the run reads as completed unless the collect checks why it
ended.

## vLLM start-up hangs

#100 logs each job's physical GPUs and their link, and climbs three start settings. With that,
the batch answers the question its hang round was built for:

| GPU pair | Link | Jobs | Base settings | `--disable-custom-all-reduce` | + `NCCL_P2P_DISABLE=1` |
|---|---|--:|---|---|---|
| 0,1 | NV12 | 14 (track A, all of arms2) | served, 70–80 s | | |
| 1,2 | SYS | 1 (track B) | hung | hung | **served** |
| 0,3 | SYS | 2 (thr2) | hung | hung | not tried (thr2 had two settings) |

With q1's job on 0,2, **4 of 4 jobs on a pair without an NVLink bridge hung, and all 14 jobs on
the bridged pair served at the base settings.** Disabling custom all-reduce does not help. Disabling NCCL peer-to-peer
served the one time it was tried, about 14 minutes after the first start, because each hung
attempt waits 6 minutes. Every hang stops right after `pynccl.py:148 vLLM is using nccl==2.30.7`,
as in q1. Peer-to-peer over PCIe between the two NUMA nodes is the likely cause; whether P2P-off
works on every unbridged pair, and what it costs in speed, is measured once.

**thr2** landed both jobs on 0,3, hung twice each, and measured nothing, so the TP=2 speed curve
and the MTP comparison are still open. **hang** asked `nvidia-smi --query-gpu` for
`minor_number`, which is not a field, read 0 GPUs, and stopped before its first start, as its
guard intended. It did record the link matrix: 0–1 and 2–3 are NV12, the other four pairs SYS.

## What should change

| Finding | Proposed change |
|---------|-----------------|
| Promotion drops an artifact's imports; 13 of 15 verified artifacts were rolled back | The foundation carries the union of its entries' imports in its header |
| A failed foundation build logs no Lean error | Log the first errors of a failed foundation build |
| A rolled-back tag is reassigned indefinitely; track B worked 4 tags in 34 generations | Tell the chair which tags keep failing or reopening, and test whether it rotates |
| A structure of free `Prop` fields closed 012U | Part of the tag-closure rule already carded: an artifact closes a statement only if it states it |
| Thinking is about 80% of output, unbounded and unsaved | Save thinking to the trace; measure a capped or disabled thinking setting before Phase C |
| A 300 s request timeout ends the run, and the job exits 0 | Decide the per-request limit together with the thinking cap; a run that ends on an exception exits non-zero |
| Unbridged pairs hang unless NCCL P2P is off | Start with `NCCL_P2P_DISABLE=1` straight away when the job's pair is SYS, and measure its speed |
| I9 gets 1–2 generations per run at 2M / 9 | Size Phase C budgets from the fixed harness, not from this rehearsal |
